# Profile README — setup

This is the content for the special **`saawyaa/saawyaa`** repo (name must equal your username).
Its `README.md` renders at the top of your GitHub profile.

## 1. Create the repo and push

```bash
cd ~/github-profile
git init
git add -A
git commit -m "Profile README"
git branch -M main
gh repo create saawyaa/saawyaa --public --source=. --remote=origin
git push -u origin main
```

> The repo **must be public** and named exactly `saawyaa`.

## 2. Give Actions write access (one time)

Repo → **Settings → Actions → General → Workflow permissions** → select
**Read and write permissions** → Save.
Without this the snake, summary-cards, and WakaTime workflows can't commit their output.

## 3. Add secrets

Repo → **Settings → Secrets and variables → Actions → New repository secret**.

| Secret | Needed by | Where to get it |
| :-- | :-- | :-- |
| `WAKATIME_API_KEY` | WakaTime stats | https://wakatime.com/settings/api-key (starts with `waka_`) |
| `GH_TOKEN` | WakaTime stats (commits README) | GitHub → Settings → Developer settings → **Fine-grained PAT** with **Contents: read/write** on this repo, or a classic PAT with `repo` scope |

`GITHUB_TOKEN` (snake, summary-cards) is built in — no secret needed.

## 4. Run each workflow once

Sections marked "generated by Action" are **blank until the workflow runs**.
Actions tab → pick each workflow → **Run workflow**:

- **Generate Snake** → creates the `output` branch with `github-snake.svg` + `github-snake-dark.svg`
- **Profile Summary Cards** → commits SVGs into `profile-summary-card-output/`
- **WakaTime Stats** → fills the block between `<!--START_SECTION:waka-->` markers

After that they run daily on their own.

## 5. WakaTime — record coding time

The WakaTime card stays empty until you log time:
1. Sign up at https://wakatime.com
2. Install the WakaTime plugin in your editor (VS Code / JetBrains / vim…) and paste the same API key.
   Time accrues as you code; the daily Action pulls the weekly summary.

## 6. Spotify "now playing" — replace the placeholder

The README has `SPOTIFY_USER_ID` in two spots (the `<img src>` and the wrapping link).
Two options:

**A. Hosted (fastest):** open
`https://spotify-github-profile.kittinan.vercel.app/`, click **Login with Spotify**,
authorize, and it gives you a ready `?uid=...` image URL. Copy that `uid` into both
placeholders in `README.md`.

**B. Self-host (private, reliable):** fork
[kittinan/spotify-github-profile](https://github.com/kittinan/spotify-github-profile),
create a Spotify app at https://developer.spotify.com/dashboard, wire Firebase + the
env vars per its README, deploy to Vercel, then log in through your own instance.
Swap the image host in `README.md` to your Vercel URL.

> If you skip Spotify: delete the `🎧 Now playing` block from `README.md`.

## Notes

- Widgets are third-party SVGs proxied through GitHub's image cache — updates lag a few minutes; that's normal.
- `github-readme-stats` runs on a shared Vercel app that can hit GitHub rate limits ("Maximum retries exceeded"). If cards flake, deploy your own instance (one-click Vercel button in [anuraghazra/github-readme-stats](https://github.com/anuraghazra/github-readme-stats#deploy-on-your-own)) and point the URLs at it.
